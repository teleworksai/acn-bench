# SPEC 080 — Hypothesis files, falsifier predicates and verdicts

**Status:** Draft v0.1 (September 2026). **Inherits:** SPEC 000, 010; reads SPEC 050 (generator modes), 085 (the loop) and 090 (attribution quantities) where noted. **Prefix:** HYP. **Crate:** `acn-hyp` (frozen set, CON-7). Numbers 17 to 19 and 29 are reserved.
**Purpose:** define the file in which a POC states its hypothesis before it runs, the small typed language in which its falsifier is written, and the only path from bundles to a verdict — such that, in `sim` mode, a negative result cannot be edited into a positive one, by a person or by a loop, without changing a hash that every bundle carries, and in `live` mode, where the same inputs yield new data on every run, a result cannot be replaced without leaving a different `bundle_digest` behind. What no file format can do is make an operator keep the runs they would rather forget; §6 says what is left to process.

## 0. Why a grammar

The report's design rule (Appendix E §E.1) is that hypotheses and falsifiers are fixed before the experiment runs, in a file no automated search loop can edit. That rule has teeth only if the falsifier is *evaluated by a machine*: a falsifier written as free text is re-interpreted every time a result disappoints. This spec therefore fixes a file format that parses strictly (HYP-1..9), a predicate language small enough to specify completely (HYP-10..16), and verdict semantics with no discretionary step (HYP-20..28).

## 1. Definitions

- **Hypothesis file** — one TOML file per POC. **Frozen** when it lives under `hypotheses/`; **candidate** anywhere else, normally `lab/hypotheses/` (CON-17).
- **Arm** — `treatment` or `control`; a session belongs to exactly one (`acn.role`, TRC-10).
- **Cell** — one assignment of values to every `[varies]` parameter. **Slice** — one assignment of values to the *non-pooled* parameters only (HYP-6); a slice contains many cells. **Replicate** — the seeded run with index `i` (CON-30a) of one arm in one cell; it is *completed* when its bundle verifies (TRC-23) and every one of its sessions has ended with an outcome on every turn (`failure`, `timeout` and `aborted` turns are data, not incompleteness). A cell is *evaluated* when the bundle set holds at least one treatment-arm bundle for it in the mode the quantities come from (HYP-21); a cell that appears only in twin bundles is listed under `twin_only_cells` and is not evaluated.
- **Quantity** — a named, documented function (HYP-12) from the view rows of one replicate to a number. Its value for an arm in a cell is the mean over replicates of the per-replicate values; the replicate is the unit of every resampling.
- **Verdict** — `pass`, `fail` or `inconclusive`, with labels.

## 2. File format

**HYP-1** A hypothesis file MUST be TOML and MUST deserialise into the typed structure of this section with unknown keys rejected at every level (`deny_unknown_fields`). A file that does not parse MUST make every command that reads it fail with the key path and the reason; it MUST NOT be partially honoured.

**HYP-2** The file MUST contain the tables `[poc]`, `[hypothesis]`, `[varies]`, `[measures]`, `[control]`, `[design]`, `[falsifier]` and `[expected]`, and no others. `[poc]` MUST carry `id` and `title`; the file stem MUST be `<id>` or `<id>-<slug>`, and an `id` MUST be unique across `hypotheses/`. `[poc]` MAY carry `spec` (the path `specs/<file>.md` of the POC spec; for a frozen file it MUST be present and MUST exist or be listed in `specs/README.md`), `report_refs` (strings: report sections, `H-n` and `G-n` identifiers), `status`, and `supersedes` (`"<id>@<hypothesis_hash>"`: a frozen file that replaces or narrows an earlier frozen hypothesis MUST carry it, and its evidence page MUST show the earlier file's verdict history, so that a failed hypothesis cannot be retired by writing a new one). `[hypothesis]` MUST carry `statement` (a string) and nothing else. `[falsifier]` MUST carry `predicate` and MAY carry the guard `inconclusive_if`, both strings (HYP-10).

**HYP-3** Status is decided by location and by the record: a file is `frozen` when it lies under `<root>/hypotheses/`, where `<root>` is the workspace root of CON-28, and `env-hash.json` lists that path with that hash; every other file is `candidate`, so that a locally edited copy, or a file moved into place but not yet recorded, cannot pass as frozen. A kit or a test fixture tree that ships its own `env-hash.json` and frozen set is such a root, which is what lets an external reproduction from the kit produce the same bundles (LOOP L4). If `[poc].status` is present it MUST equal the status so determined; a mismatch is a parse error. Every bundle MUST record the status (`acn.hypothesis.status`, TRC-10), and it is a run parameter (`hyp_status`, CON-29), so that two copies of one file with different status never share a `run_id`.

**HYP-4** Automated agents, search loops and CI jobs MUST NOT hold write access to `hypotheses/` (CON-7 covers the rest of the frozen set). The `acn-hyp` library and the `acn hyp` and `acn loop` subcommands MUST open hypothesis files read-only, MUST NOT write anywhere outside `runs/`, and MUST abort with `hypothesis_changed` if the hash of a hypothesis file changes while a loop is using it (LOOP-13).

**HYP-5** `hypothesis_hash` MUST be computed as CON-27(a) specifies, over the file's bytes. Whitespace and comments are therefore part of the hash, and a frozen file MUST NOT be reformatted. Comments are not normative: where a comment and this spec disagree (for example on how seeds are derived), this spec governs.

**HYP-6** `[varies]` maps each parameter name to exactly one of `{ kind = "bool" }`, `{ kind = "enum", values = [...] }`, `{ kind = "range", min = x, max = y }` (numeric, inclusive) or `{ kind = "int_range", min = a, max = b }`. `min` and `max` MUST be finite with `min ≤ max`; `values` and `levels` MUST be non-empty and free of duplicates, and every level MUST lie in the domain and, for an `int_range`, be an integer. A `range` or `int_range` MAY carry `levels = [...]`, and MUST carry it when `[design].search = "grid"`. These are the only parameters a loop may vary (LOOP-10); a sample outside the declared domain MUST be rejected before the run starts. A parameter MAY carry `pooled = false`: results are then computed per value of that parameter and never pooled across values (HYP-24); it is permitted only on a `bool` or `enum` parameter, or on one that carries `levels`, so that the slices are a finite, declared set. The parameter named `provider` is non-pooled whether or not it says so (CON-26). Enum values MUST be unique across all parameters of a file. Parameter names, enum values and quantity names MUST NOT be reserved words (HYP-10). The value of every parameter for a bundle is read from the manifest's `params` (`vary.<name>`, CON-29), never inferred from `acn.backend`; a verdict checks that the two agree (HYP-20).

**HYP-7** `[measures]` MUST carry `primary` and MAY carry `secondary`, each a list of quantity names. A predicate MAY reference only quantities listed here. For a frozen file every name MUST resolve to a quantity definition (HYP-12) when the file is loaded; for a candidate an unresolved quantity is a warning, and a verdict that needs it is `inconclusive` (so that a lab idea does not need a change to a frozen crate before it can be written down, CON-23).

**HYP-8** `[control]` MUST carry `description`. A frozen file MUST also carry exactly one of `config` and `workload`; a candidate MAY omit both, and its verdicts are then `inconclusive` (CON-18). `config` is a table assigning values, each within its domain, to some or all pooled parameters; every parameter it does not assign is inherited from the treatment cell. Control runs are keyed by their *effective configuration* (the assigned values plus the inherited ones): there MUST be exactly one control bundle (`arms = "control"`, `vary.*` = the effective values) per distinct effective configuration per slice, and it is the control arm of every treatment cell that maps to it, so that identical control runs are never repeated per cell. `workload` names the generator mode (SPEC 050) that produces a different workload (plain RPC, file transfer) under the same scenario as the treatment (CON-18): it is run once per distinct assignment of the parameters listed in `[control].inherits` (default: every `range` and `int_range` parameter, and any enum parameter the generator mode declares that it reads), and it is the control arm of every treatment cell that agrees with it on those parameters. `q(control)` is per-cell accordingly.

**HYP-9** `[design]` MUST carry `search` (`grid`|`bisect`|`random`), `replicates` (an even integer ≥ 4; in a frozen file ≥ 20, because a percentile bootstrap over four pairs rejects at 12.5% where it claims 5%) and `twin_required` (bool; `false` is permitted only for network-free hypotheses, LOOP-4). A frozen file MUST use `search = "grid"` until a spec-change defines which cells an adaptive design has to cover (§6, question 2); `bisect` and `random` are for candidates. `[design]` MAY carry `seeds` (only the value `"derived"`, meaning CON-30a) and, in a candidate only, `seed` (a run seed, an integer from 0 to 2^63−1). A frozen file MUST NOT carry `seed`: its run seed MUST be the derived seed (CON-30) of `blake3("acn-bench/hypothesis_seed/v1\0" ‖ hypothesis_hash)`, and a verdict MUST refuse frozen-hypothesis bundles run under any other seed, so that a frozen hypothesis cannot be re-run under fresh seeds until it passes. This does not stop a seed being chosen *before* freezing, because every byte of the file, a comment included, changes the hash (§6, question 6). A candidate with no `seed` derives it the same way from its own hash; a command-line seed is accepted only for hypothesis `none`; and a loop's search seed is the sub-stream `loop.search` of the run seed (CON-30b), not a free input. `[design]` MAY also carry `backends` (a list drawn from `"mockllm"` and `"real-api"`, the two ways of providing inference; which real providers run is the `provider` parameter), `min_providers_for_verdict` (an integer from 1 to the number of declared providers, default 1; permitted only when the file has a `provider` parameter), `sim_live_tolerance` (a table from `[measures]` quantity names to a tolerance, CON-25: a number, meaning relative and at most 0.5, or `{ abs = x }`; finite and greater than zero) and `pins` (a table with `scenario` and `workload`, each a list of BLAKE3 hex digests, and `models`, a table from provider value to the exact model identifier: the inputs the hypothesis is about, HYP-20). When `twin_required` is true, every quantity that the predicate reads MUST have a tolerance, or the file fails to load. `[expected]` MUST carry `outcome` (`pass`|`fail`) and MAY carry `note`; it is recorded in the verdict and MUST NOT affect it.

## 3. The predicate language

**HYP-10** `[falsifier].predicate` and `[falsifier].inconclusive_if` are strings in the language below and MUST be parsed and type-checked when the file is loaded; one that fails makes the file fail to load. The falsifier evaluates to a boolean: **true means the hypothesis is refuted**. The guard `inconclusive_if` MUST be built only from the counters, numbers, comparison, `and`, `or`, `not` and parentheses: a quantity, a `select`, a built-in or an `at` clause in it is a load error, because a guard that could read outcomes could be written to turn every `fail` into `inconclusive`; and a guard that reads `providers_reported` in a file with no `provider` parameter is a load error. Reserved words are `and`, `or`, `not`, `at`, `all`, `any`, `cells`, `control`, `treatment`, `ci`, `true`, `false`, the counters `replicates` and `providers_reported`, and the built-in names of HYP-13. A parser needs two tokens of lookahead to tell `ident "="` from an expression that starts with an identifier, and in a `barg` the built-in's signature (HYP-13) selects the alternative: where it expects a quantity reference the argument MUST be a bare `qname`. A `number` carries no sign; the bound of an `at` clause and a selector value are `snumber`s, so that a negative level can be named; `ci` MUST lie strictly between 0 and 1.

```
expr     := or ( "at" ( "all" | "any" ) ( pname cmpop snumber | "cells" ) )?
or       := and ( "or" and )*
and      := not ( "and" not )*
not      := "not" not | cmp
cmp      := sum ( cmpop sum )?
cmpop    := "<" | "<=" | ">" | ">=" | "==" | "!="
sum      := term ( ( "+" | "-" ) term )*
term     := unary ( ( "*" | "/" ) unary )*
unary    := "-" unary | atom
atom     := number | builtin | select | counter | qname | "(" expr ")"
select   := qname "(" selector ( "," selector )* ")"
selector := "control" | "treatment" | pname "=" value | evalue
builtin  := fname "(" barg ( "," barg )* ")"
barg     := "ci" "=" number | "control" | "treatment" | qname | expr
counter  := "replicates" | "providers_reported"
qname    := a name listed in [measures]
pname    := a parameter of [varies]
value    := evalue | "true" | "false" | snumber
snumber  := "-"? number
evalue   := an enum value of [varies]
fname    := one of the built-ins of HYP-13
number   := [0-9]+ ( "." [0-9]+ )? ( ( "e" | "E" ) ( "+" | "-" )? [0-9]+ )?
ident    := [a-z_][a-z0-9_]*          (qname, pname, enum values and fname are idents)
```

The `at` clause has the lowest precedence and applies to the whole predicate, so `A or B at all x <= 1` means `(A or B) at all x <= 1`; `at all cells` and `at any cells` range over every evaluated cell of the slice, for designs whose parameters are all `bool` or `enum` and so have nothing to bound (a Pareto falsifier needs "in some cell, A and B both hold", which no aggregate expresses). An identifier followed by `(` is a `builtin` when it is one of the names of HYP-13 and otherwise MUST be a `qname`, which makes it a `select`; any other name is an error.

**HYP-11** The language MUST be statically typed with three types: *number*, *boolean* and *quantity reference* (a `qname` given to a built-in that expects one). There is no implicit conversion. Comparison takes numbers and yields a boolean; `and`, `or`, `not` take booleans; arithmetic takes numbers and is IEEE-754 double precision, a NaN or infinite result being undefined. Quantities carry a unit (HYP-12): `+`, `-`, comparison, `min` and `max` MUST be given operands of one unit, a bare number and the result of `*` or `/` being compatible with any; a mismatch is a load error, so that milliseconds are never added to tokens. A value is *undefined* when it has no data: a cell with fewer completed replicates in an arm than `[design].replicates`, a replicate whose own value is undefined (it makes the arm undefined and is listed; it is never skipped, because dropping failed replicates is survivorship bias), a division by zero, an unresolved quantity (HYP-7). Undefined MUST propagate strictly through arithmetic, comparison, every built-in and every aggregate. The boolean connectives use Kleene's three-valued logic: `false and U` is false, `true or U` is true, `not U` is U, `at any` is true when some cell is true, and `at all` is false when some cell is false, whatever the other cells hold. The verdict rule that follows (HYP-21) is asymmetric on purpose: a falsifier that is true refutes, even if other cells are missing, so that a crash or an abandoned run cannot shield a hypothesis from a refutation the data in hand already establishes; a `pass` needs the falsifier to be false **with no undefined operand anywhere in it**, so that missing data can never produce one.

**HYP-12** Names MUST resolve as follows. A bare `qname` is the quantity's value in the treatment arm of the current cell. In a `select`, `control` and `treatment` choose the arm, `pname = value` fixes a parameter, and a bare `value` fixes the one parameter that declares it (values are unique across parameters, HYP-6); a parameter fixed by a selector is excluded from the cells an `at` clause or an aggregate ranges over. A bare value selector MUST be an enum value; a bool or a number is written `pname = value`. A `select` MUST NOT name both arms, fix one parameter twice, or give a parameter a value outside its domain. A parameter that one `select` of a predicate fixes MUST be fixed, to some value, in every other treatment-arm term of that predicate — every other `select` that does not choose `control`, and a predicate that fixes a parameter anywhere MUST NOT also use a bare `qname` or a per-cell built-in, which would leave it free. `q(control)` is the control arm the cell maps to (HYP-8), the cell being the complete treatment configuration with fixed parameters at their fixed values; a predicate that contains a `control` term MUST therefore fix each parameter to at most one value across its treatment-arm terms, or the control would not be determined. A selector MUST NOT fix a non-pooled parameter: inside a per-value verdict (HYP-24) only one value exists. The counters belong to the guard (HYP-10), which is evaluated once, at file level (HYP-24): `replicates` is the minimum, over the slices of reported providers (over all slices when the file has no `provider` parameter), their evaluated cells and both arms, of the number of completed replicates with index in `0..[design].replicates`; `providers_reported` is defined by HYP-24. A predicate MAY read `replicates`, as the same minimum within its slice, and MUST NOT read `providers_reported`. Quantities MUST be defined in one table in `acn-hyp`: name, unit, a documented formula over named view columns and `acn.*` promoted columns only (TRC-3), and any named constants it needs (for example the per-provider price table behind `cost_per_success`, which lives in the frozen crate and so moves `engine_hash`, CON-28); attribution quantities such as `network_attributable_share` are defined by SPEC 090 and registered here by name. The table MUST be rendered by `cargo xtask docs-inventory`.

**HYP-13** The built-ins MUST be exactly these, and an unknown `fname` is an error. Over numbers: `abs(x)`, `min(x, y)`, `max(x, y)`. Taking a quantity reference `q` and evaluated per cell: `effect(q)` = `q(treatment) − q(control)`; `rel_effect(q)` = `effect(q) / q(control)`; `ci_low(q, ci = 0.95)` and `ci_high(q, ci = 0.95)`, the bounds of the percentile-bootstrap confidence interval of `effect(q)` (HYP-15). Aggregates over the evaluated cells of the current slice, each yielding one slice-level number: `max_over_knobs(x)` and `min_over_knobs(x)`. Slice-level by definition: `noise_floor(q, control, ci = 0.95)`, computed for each control bundle of the slice (there is exactly one per distinct effective configuration, HYP-8, so "the control replicates" is never a pool across cells) as half the width of the percentile-bootstrap confidence interval of `stat(even) − stat(odd)`, where *even* and *odd* are the control replicates with even and odd index among `0..replicates` and `stat` is the mean of the per-replicate values; the two halves are resampled independently, `replicates/2` draws each, the even half first; and then taken as the **largest** such value in the slice (the conservative choice: it makes a small effect harder to call real). A `noise_floor` of exactly zero is undefined: no run-to-run variation was observed, so nothing can be called above or below it. The arguments `control` and `treatment` are accepted only where listed here.

**HYP-14** Every sub-expression is either *per-cell* (it mentions a bare `qname`, a `select` that leaves pooled parameters free, or a per-cell built-in) or *slice-level* (numbers, counters, aggregates, `noise_floor`, and a `select` that fixes every pooled parameter). A per-cell predicate MUST carry an `at` clause, or be wrapped in aggregates, whenever the design has more than one cell in a slice; otherwise the file MUST be rejected as ambiguous. `P at all v <= c` holds when `P` holds in every evaluated cell of the slice whose parameter `v` satisfies the bound, and `at any` when it holds in at least one; with no such cell the result is undefined, and a cell that is undefined enters as HYP-11 says. Cells are ordered by parameter name, then by value: numerically for numbers, `false` before `true`, and in declaration order for enum values.

**HYP-15** Evaluation MUST be deterministic. Bundles are processed in ascending (`run_id`, `bundle_digest`) order whatever the argument order. `verdict_id = blake3("acn-bench/verdict_id/v1\0" ‖ hypothesis_hash ‖ pairs)`, the pairs being each bundle's `run_id` and then its `bundle_digest` (TRC-23), as raw digests in that order, so that a verdict over re-run data has a different id. The verdict seed is the derived seed (CON-30) of `blake3("acn-bench/verdict/v1\0" ‖ hypothesis_hash)`: it depends on the hypothesis alone, so that adding an ignored replicate or a twin bundle to the set cannot be used to search for favourable resampling noise. Every bootstrap uses `B = 10 000` resamples of replicates, drawn from its own sub-stream `hyp.bootstrap/<slice key>/<cell key>/<quantity>/<function>` derived as in CON-30(b) with the verdict seed as `s`, so that no draw depends on evaluation order. A key is its `name=value` pairs sorted by name and joined by `,`, with values in the text form of CON-27(c); the slice key is empty for a file with one slice; for `noise_floor` the cell key is the control's effective configuration. `<function>` is `effect` for `effect`, `rel_effect`, `ci_low` and `ci_high` alike, so that both bounds of an interval come from one set of resamples, and `noise_floor` for `noise_floor`; the confidence level is not part of the key, and every `ci` reads the same resamples. For `effect`, treatment and control are resampled **as pairs by replicate index** (the arms share `replicate_seed(i)`, and an evaluated cell has every index in both). Resample `b` draws `n` indices in order, `n` being the number of replicates resampled (`[design].replicates` pairs for `effect`, `replicates/2` for each half of `noise_floor`), each with the ranged-integer sampler over `0..n` whose output CON-5(a) pins by golden vector; its statistic is the mean of the drawn treatment values minus the mean of the drawn control values, each mean summed in draw order. With the `B` statistics sorted ascending and indexed from zero, let `k = round_half_even(B × (1 − ci) / 2)`, evaluated in double precision from left to right; the lower bound is the value at index `k` and the upper bound the value at index `B − 1 − k` (250 and 9749 at the default; the rounding matters at levels such as 0.9, where the exact product is an integer that floating point misses, and a known-answer test MUST cover one). `verdict.json` MUST be UTF-8 JSON with sorted keys, no insignificant whitespace, numbers in the text form of CON-27(c), an undefined value as `null`, and one trailing newline; its arrays are ordered: slices by slice key, cells as HYP-14 orders them, reasons as HYP-21 lists them, bundles ascending. The same bundles and the same hypothesis file MUST yield a byte-identical `verdict.json`.

**HYP-16** The predicates of the two files that existed when this spec was accepted MUST load under it unchanged: `hypotheses/p4.toml` — `max_over_knobs(abs(effect(cost_per_success))) < noise_floor(cost_per_success, control, ci = 0.95)`, a comparison of two slice-level numbers, with the guard `replicates < 20 or providers_reported < 2` — and `lab/hypotheses/p17-a2a.toml` — `network_attributable_share(a2a) - network_attributable_share(control) < 0.05 at all rtt_ms <= 150`, two `select`s, the first fixing `protocol` by its unique value `a2a`. Both files also satisfy §2 as they stand (`p17` by the `<id>-<slug>` stem rule and the candidate allowances of HYP-7, HYP-8 and HYP-9; `p4` carries no `pins`, so its verdicts are labelled `unpinned-inputs` until a Class C PR adds them, HYP-23). The test MUST use byte-for-byte copies of both files under `crates/acn-hyp/tests/fixtures/`, pinned by BLAKE3 in the test, because a candidate may be edited by anyone and a frozen crate's test must not break when it is; `hypotheses/p4.toml` is additionally loaded from its real path. An implementer who finds that a file needs an edit to conform reports it to the owner and does not edit the file (CON-7). That a predicate loads says nothing about whether it is good science: §6, question 1.

## 4. Verdicts

**HYP-20** `acn hyp verdict --hypothesis <file> <bundle>…` MUST be the only path from bundles to a verdict (CON-17). It MUST verify each bundle (TRC-23) and MUST refuse: a bundle whose `hypothesis.hash` differs from the file's; a set whose bundles disagree on `engine_hash`, or whose `engine_hash` differs from the tool's own, which is the value its binary embedded (CON-31) and CON-28 has already checked against the checkout; a set with more than one `build_hash` within one mode; two bundles that cover the same slice, cell, arm, mode and replicate index; a set that mixes `mockllm` and real backends; a treatment bundle and the control bundle it maps to, or a sim bundle and its live twin, that differ in `scenario_hash`, or in `workload_hash` unless the control is a `workload` control (HYP-8); bundles of one slice that differ in `backend` or `model`; a bundle whose `vary.provider` differs from its `backend`, unless the backend is `mockllm`; a bundle whose `scenario_hash`, `workload_hash` or `model` is not among `[design].pins`, when the file has them; a set that mixes `new_input_tokens_method` values (TRC-12); a frozen-hypothesis bundle run under a seed other than HYP-9's; and an existing verdict directory, which is never overwritten. It MUST write `runs/verdicts/<verdict_id>/verdict.json` (HYP-15) and MUST print `{"ok": true, "verdict_id": …, "verdict_path": …, "run_ids": […], "verdict": <that object>}` (CON-8): `ok` reports that the evaluation completed, whatever the verdict, and a refusal prints `"ok": false` with the reason. Verdicts are not part of any bundle (TRC-22).

**HYP-21** The verdict of one slice MUST be computed by these rules and nothing else. If the set contains sim bundles, quantities and replicate counts come from the sim bundles only, live bundles are read only by the twin rule (HYP-22), and netem bundles are refused until the M4 rules are written. If it contains only live bundles, or only netem bundles, they come from those, and the twin rule does not apply, since nothing simulated is relied on. A set that mixes live and netem with no sim bundle is refused until M4. Only replicate indices `0..[design].replicates` are read: a session whose `acn.replicate` is at or beyond the design count is *ignored*, whatever bundle holds it, and the bundle is listed under `ignored_replicates`, so that running until a result looks good changes nothing. The slice verdict is `inconclusive`, without the falsifier being consulted, if the control arm is missing (CON-18), if no cell is evaluated, or if the twin rule of HYP-22 fails, because a refutation that rests on a simulator shown to diverge is not a refutation. Otherwise the falsifier is evaluated under HYP-11, an evaluated cell with an incomplete arm and, for `search = "grid"`, a grid cell with no runs being undefined: the slice verdict is `fail` if the falsifier is true, `pass` if it is false with no undefined operand, and `inconclusive` otherwise. `reasons[]` MUST list every cause that applied, by these identifiers and in this order: `control_missing`, `no_evaluated_cell`, `twin_failed`, `incomplete_cell`, `grid_cell_missing`, `undefined_value`, and at file level (HYP-24) `guard`, `slice_inconclusive`, `providers_below_minimum`, `no_conclusive_slice`; each carries the cells or the expression it refers to.

**HYP-22** Twin rule (CON-25). What it decides is whether the simulator may be trusted for the cells a verdict rests on. A sim bundle can only use the mock backend (`sim` has no sockets, PLAN §2), so a sim-based verdict is `mock-gated` and never citable by itself; what the twin rule licenses is promotion to the next layer of SPEC 085, where real-provider live bundles are evaluated on their own. `acn hyp verdict` MUST compute sim↔live divergence itself, from sim and live bundles paired by cell, arm and replicate index. For each quantity with a tolerance, the divergence of a cell and arm is `|mean_live − mean_sim|` over the replicate indices present in both modes, divided by `|mean_sim|` for a relative tolerance (a zero `mean_sim` makes it undefined) and taken as it is for an `abs` tolerance; the cell's divergence is the larger of its arms'. For a quantity the predicate reads through `effect`, `rel_effect`, `ci_low` or `ci_high`, the divergence of the effect, `|effect_live − effect_sim|`, relative to `|q_sim(control)|` or absolute in the same way, MUST also be within the tolerance, so that a sim and a live run that agree arm by arm while disagreeing on the sign of the effect do not pass. The *decision cells* of a slice are the cells at which each `max_over_knobs` and `min_over_knobs` attains its value and the cells that decide each `at` clause (every cell in its range when `at all` holds or `at any` fails, otherwise the first deciding cell in HYP-14 order); they are computed from the sim bundles, never chosen by the operator. The replicate-count rule does not apply to live bundles, but a decision cell is *twinned* only when both of its arms have live bundles with at least `replicates / 2` paired indices. When `twin_required` is true, a cell that has live bundles and whose divergence exceeds a tolerance, or is undefined, fails the twin rule (HYP-21). A verdict all of whose decision cells are twinned carries no twin label; one with no live bundle is labelled `sim-only`, and one with some decision cells untwinned `partially-twinned`. Both are evaluated normally: this is what the loop runner uses at L1 (LOOP-10), and LOOP-12 then twins the decision cells.

**HYP-23** Labels: `exploratory` when the file is a candidate **or any bundle's manifest records `hypothesis.status = "candidate"`**, so that a candidate's runs cannot become evidence by moving the file afterwards; `mock-gated` when any bundle has `backend = "mockllm"` (CON-26); `sim-only` and `partially-twinned` as HYP-22 defines, for a verdict whose quantities come from sim bundles; `partial-providers` as HYP-24 defines; `unpinned-inputs` when a frozen file with `real-api` among its backends carries no `[design].pins`, because nothing then says which scenario, corpus or model the hypothesis was about, and a failing set could be replaced by a passing one on other inputs. A verdict carrying `exploratory`, `mock-gated` or `unpinned-inputs`, or carrying `sim-only` or `partially-twinned` while `twin_required` is true, MUST NOT be rendered as citable on an evidence page (LOOP-30). A verdict carrying `partial-providers` MAY be, and MUST then be shown with the providers that were not run.

**HYP-24** Non-pooled parameters split the evaluation: there MUST be one slice verdict per combination of their values (for `provider`, one per provider), reported side by side. The file-level verdict is then computed once. A provider value is *reported* when every slice with that value is conclusive, and `providers_reported` is the number of reported values. The guard `inconclusive_if` is evaluated here, once, with the file-level counters (HYP-12). The file-level verdict is `inconclusive` if the guard is true or undefined; or if any slice for which the set holds at least one bundle is `inconclusive`, so that a provider cannot be run, found wanting and left half-submitted to drop it from the count; or, for a file that has a `provider` parameter, if `providers_reported < [design].min_providers_for_verdict`; or, for a file that has none, if any slice is `inconclusive`; or if no slice is conclusive. Otherwise it is `fail` if any slice verdict is `fail`, and `pass` otherwise. `verdict.json` MUST list every declared provider value as `pass`, `fail`, `inconclusive` or `not_run`, and a verdict in which any is `not_run` carries the label `partial-providers`: the minimum is a pre-registered allowance for providers the operator cannot reach, and which ones were left out MUST be visible wherever the verdict is shown (§6, question 7, on the stricter alternative). An all-mock set yields a file-level verdict, which carries `mock-gated` and is not citable (HYP-23). A file with no non-pooled parameter has one slice, and its verdict is the file-level verdict once the guard has been applied.

**HYP-25** A `fail` on a frozen hypothesis is a result. Tooling MUST NOT offer an option to relax, rewrite or re-scope the hypothesis, and MUST record a `fail` on the evidence page like any other verdict (LOOP-3).

**HYP-26** Freezing: a candidate becomes frozen by a Class C PR that moves the file to `hypotheses/`, removes or corrects `[poc].status`, adds its POC spec and, for `real-api` hypotheses, its `[design].pins`, and updates `env-hash.json`. The PR MUST precede the first run whose bundle is cited (CON-17). `cargo xtask env-hash --check` failing on a changed hypothesis file is the freeze check.

**HYP-27** `acn hyp lint <file>` MUST parse a hypothesis file, type-check its predicates, resolve its quantities and print the parsed structure and warnings, without reading any bundle. For a file under `hypotheses/` it MUST also fail unless the predicate reads at least one primary quantity and lint finds a witness pair: one assignment of probe values under which the falsifier is true and one under which it is false, each distinct quantity term (per arm, the same in every cell), each `noise_floor` and each interval bound being drawn from {0, 1e-9, 1, 1e9} with `ci_low ≤ ci_high`. A predicate that can never fire, or can never fail to fire, is not a falsifier. It SHOULD warn when a per-cell comparison uses neither an interval bound nor `noise_floor`, and when an `at all` ranges over more than one cell while comparing point estimates. CI MUST run it on every file under `hypotheses/`, where a failure fails the build. On files under `lab/hypotheses/` it is advisory: the result is reported and MUST NOT fail the build (CON-23).

**HYP-28** `verdict.json` MUST carry: `verdict_id`, `verdict`, `reasons[]` (HYP-21), `slices[]` (each with its parameter values, verdict, reasons and labels), the status of every declared provider value (HYP-24), `hypothesis {id, status, hash}`, `expected`, `labels[]`, the `run_id` **and `bundle_digest`** of every bundle read, `ignored_replicates` (bundle and replicate indices ignored under HYP-21), `twin_only_cells`, `engine_hash`, every distinct `build_hash`, the value of every quantity and sub-expression the predicates evaluated (per slice, cell and arm, with replicate counts and confidence intervals), the decision cells, which of them are twinned, and the twin divergences of quantities and effects (HYP-22), and the treatment-minus-control effect of every primary quantity (CON-18).

## 6. Open questions (ADR candidates)

1. **The statistic of POC 4.** `noise_floor` is a split-half control statistic, and `hypotheses/p4.toml` compares a maximum over several hundred treatment cells with the largest split-half floor of a few control configurations. Nothing calibrates that comparison: a rough simulation during review found that it passes a null hypothesis often when replicates are independent, and how often depends on how much replicates differ, which is a property of the workload. The predicate also yields `pass` for a degenerate run in which every cost is identical, which the zero-floor rule of HYP-13 now turns into `inconclusive`. SPEC 100 MUST settle, before any real-provider run of POC 4, whether the falsifier needs a simultaneous interval or a null distribution of the searched maximum, as a new built-in rather than a change to this one; and whether a parameter that has no meaning for some providers (`cache_breakpoint_placement`) needs conditional domains. The predicate of `lab/hypotheses/p17-a2a.toml` has a related weakness: it compares point estimates under `at all`, so one noisy cell protects the hypothesis, and it never tests the "stays below 5%" half of its statement. HYP-16 preserves that these predicates *load*; it does not endorse them.
2. **Adaptive designs.** `bisect` and `random` choose their cells after seeing data, so "every evaluated cell" is a set the operator can steer. Frozen files are therefore `grid` only (HYP-9). Lifting that needs a coverage rule, a frozen sample count and search seed, a requirement to submit every generated cell, and probably a `crossing(q, threshold)` built-in so a boundary-finding falsifier (POC 1a, POC 7) can state "no crossing exists" directly.
3. Whether per-value verdicts (HYP-24) should generalise beyond `provider` to endpoint class in POC 1a.
4. The owner may wish to tidy two things in the existing files while it is cheap: the seeds comment in `hypotheses/p4.toml` shows an un-prefixed formula that CON-30(a) supersedes, and `provider` could say `pooled = false` explicitly. `p4.toml` also needs `[design].pins` before its real-provider verdicts can be cited (HYP-23).
5. LOOP-10 stops a loop "when the falsifier's confidence interval no longer straddles its threshold". A falsifier here is a boolean, and HYP-21 reads a fixed replicate set, so that stop rule needs restating in SPEC 085 in terms this spec defines (for example: every cell has its `replicates`, or the budget is spent). That is a follow-up `spec-change`, not part of this one.
6. **Choosing the seed before freezing.** The frozen seed is derived from the file's hash, and any byte of the file changes the hash. Someone who holds the final bytes can compute the seed, preview the sim result under it in a candidate copy, and vary a comment until the preview pleases. Canonicalising the TOML would not help, since free-text fields can be varied too. The real remedies are entropy the author does not control and that post-dates the bytes (a public randomness-beacon round after the freeze merge, recorded in `env-hash.json` and mixed into the seed) or a second party choosing it. Until one is adopted, the derived seed protects a frozen hypothesis from re-runs, not from its author.
7. **Runs that were never kept.** In `live` mode, against real providers, the only mode whose verdicts can be cited, the seed does not determine the data. CON-29 now refuses to overwrite a bundle and `bundle_digest` makes a re-run visible as different data, but `runs/` is not versioned, and nothing records that a run was made and deleted. The SPEC 085 follow-up should add: an evidence page that shows every verdict ever committed for a hypothesis id, across `engine_hash` values, with removal treated like a gate-record change; `acn evidence verify` failing unless the verdict's `engine_hash` and the hypothesis hash match the *committed* `env-hash.json` of the commit being verified (a directory under `lab/` that holds its own `env-hash.json` is otherwise a root, CON-28); a `pre-freeze` label for live bundles that started before the mainline commit that introduced the hypothesis hash; an `unattested-build` label when `source_hash` matches no mainline tree; and a campaign plan with an attempt counter. The stricter alternative to `partial-providers` (HYP-24), that a `pass` needs every declared provider, belongs to the same decision.
8. **Independence of replicates.** The replicate is the unit of every resampling, yet on a real provider replicates share a prefix cache, throttling and load, and every cell of a slice shares one control bundle and one seed schedule, so cell effects are correlated and the `max`, `at all` and `at any` constructs ignore it. CON-5(d) now derives and records the execution order; cache isolation between arms and replicates, cool-down and blocking belong to SPEC 040 and the POC specs.
9. Multiplicity across the catalogue: sixteen or more POCs at a nominal 95% each have no family-wise statement, and a predicate may `or` several primary quantities. SPEC 095 should say what the programme claims as a whole.
10. **The independent party.** A Class C freeze review is the only guard on wide literals, generous tolerances and an unjustified `twin_required = false`, and HYP-4 assumes agents cannot write `hypotheses/`. While one account holds every permission (ADR-6), these are statements of intent. This spec moves what it can into lint and the verdict engine; it cannot supply the second person.
