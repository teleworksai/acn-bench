# Lab note — p1a-atlas: POC 1a by hand, to find what SPEC 110 has to decide (2026-11-12)

Crate: `lab/p1a-atlas`. Candidate: `lab/hypotheses/p1a.toml`. Track: lab (CON-23).
**Every number here is exploratory and may not be cited (CON-24).** Mock backend
(`mock-auto`), guessed link numbers, four replicates a cell, one machine (macOS arm64).

## Question

TASKS.md gives POC 1a one line: a 3×3 grid of placement and profile, the 5% boundary, a
heatmap, and a REST workflow as control. Nothing else in the repository defines it. Before
SPEC 110 is written:

1. Can the run path produce the grid at all, in sim and in live, with a verdict and a twin?
2. What does it show on the mock, and what is missing before any of it could be a result?

## What was tried

**The grid.** Nine scenario files, `lab/p1a-atlas/scenarios/<placement>-<profile>.toml`.

| placement | one-way delay | round trip |
|---|---|---|
| `edge` | 2.5 ms | 5 ms (wired only; see below) |
| `regional` | 20 ms | 40 ms |
| `remote` | 80 ms | 160 ms |

| profile | what it adds to the delay |
|---|---|
| `wired` | nothing |
| `wifi` | 3 ms jitter, 0.5% independent loss, 50/100 Mbit/s |
| `cellular` | the stages of `scenarios/synthetic/cellular-handover.toml` without its handover and without its uplink reorder stage: burst loss up, 0.2% loss down, 20/100 Mbit/s, 8/5 ms jitter |

On the jittered profiles `edge` is not a 5 ms round trip. The jitter's half-range is
larger than the 2.5 ms base and the delay is clamped at zero, so the mean one-way delay
rises: 3.1 ms up and 3.5 ms down on `edge-cellular` (review run). That is why the
control reads 21.6% there against 17.6% on `edge-wired`.

**The arms.** Treatment: `workloads/agent.toml`, one task of four turns, local tools.
On `mock-auto` each turn is two calls: a one-token tool call (about 64 ms) and a
streamed answer of up to 64 tokens (about 1.33 s, about 69 downlink messages). Control:
`workloads/rpc.toml`, four exchanges with no tools, no streaming and a one-token reply.
**The control is a stand-in.** The plain-RPC control of CON-18 does not exist (SPEC 050,
T13b); this one still goes through the harness and the mock. `workload =
"request_response"` in the candidate is a free label: no such generator mode exists, and
the verdict only checks that a control and its treatment share a scenario. The
falsifier does not read the control at all (a bare quantity is the treatment arm); the
control is there to be measured beside it and to be twinned.

**The driver.** `acn loop run` runs with no scenario (ADR-34), and it refuses a `workload`
control. So `lab/p1a-atlas` calls `acn harness run --scenario …` once per cell, arm and
mode, with `--vary placement=… --vary profile=…`, then `acn hyp verdict` over the 36
bundles, and `acn attrib heatmap`. `placement` and `profile` are not knobs: the harness
records them and ignores them, and the driver is what ties a pair to a scenario file.

Run, from the repository root, with `acn` built:
`lab/p1a-atlas/target/debug/lab-p1a-atlas --runs-dir <dir>/runs --modes sim,live`.
Sim takes 6 s; sim and live together took 305 s. The verdict reads replicate indices
`0..[design].replicates` only, so `--replicates` above the file's 4 changes nothing
until the file is edited too.

A second session reviewed this note on PR 104 and re-ran everything. Where a figure
below says "review run", it is that session's, read from the bundles' views, and was
not re-derived here.

## What was learned

### It runs, end to end

Sim, live on the served mock through the proxy, a verdict with a `workload` control that
inherits both parameters, the twin rule and the heatmap all work on hand-made bundles
with one scenario per cell. Nothing in the frozen set had to change for that.

### The numbers (sim; share of turn time)

| cell | agent: network | agent: retry | stand-in control: network |
|---|---|---|---|
| edge, wired | 0.7% | 0 | 17.6% |
| edge, wifi | 0.7% | 27.4% | 17.8% |
| edge, cellular | 0.8% | 17.9% | 21.6% |
| regional, wired | 5.6% | 0 | 63.1% |
| regional, wifi | 4.2% | 27.1% | 63.1% |
| regional, cellular | 4.7% | 17.7% | 63.3% |
| remote, wired | 19.3% | 0 | 87.2% |
| remote, wifi | 14.3% | 26.1% | 87.2% |
| remote, cellular | 15.9% | 17.0% | 87.3% |

1. **On the wired column the agent's network share passes 5% somewhere between 5 and
   40 ms round trip.** Three placements bracket the crossing and do not locate it; at
   40 ms the wired cell is 5.6% and the lossy ones are 4.2% and 4.7%. The candidate's
   falsifier, `max_over_knobs(network_attributable_share) >= 0.05`, is true: sim verdict
   `fail`, decision cell `remote, wired`. Where the crossing falls is set by the mock's
   20 ms a token and the 64-token answers, which are choices of this note.
2. **The agent's share is far below the stand-in control's on every cell**, because model
   time fills an agent turn. An `effect` against this control is negative everywhere
   (the heatmap draws that). "Agent minus plain RPC" may be the wrong way round for a
   sensitivity atlas; see the decisions below.
3. **What a lost message costs depends on which message it is, and the table above shows
   only one of the cases.** Nothing retransmits a dropped message (SPEC 020 EMU-35;
   the harness's retry is HAR-24).
   - *A stream that loses an event and then receives a later one* is cut ("the network
     cut the stream") and the call is made again. That is every loss in the table: at
     four replicates no bundle lost anything else. It is counted as `retry_share`, and
     the network share goes *down* on the lossy profiles because the turn got longer.
   - *A lost request, a lost non-streamed reply or a lost end of stream* waits for the
     attempt's deadline, `opt.request_timeout_ms`, 600 s by default, and attribution
     counts that wait as network time (ATR-11). In the review run at 20 replicates one
     request is lost in each wifi agent bundle: the call ends `client_abort` after 600 s,
     that replicate's network share is 0.993, and the cell's mean moves from 0.7% to
     5.6% (edge), 4.2% to 9.1% (regional) and 14.3% to 19.1% (remote).
   - So a lossy cell's number is set by the retry cap, the backoff and the 600 s
     timeout before it is set by the link. A TCP connection would have turned most of
     these losses into delay.
4. **`retry_share` is mostly the default backoff, and one turn in sixteen failed.**
   `retry_ns` includes backoff (ATR-11), 500 ms doubling: 7.0 s of about 9.4 s on wifi and
   2.5 s of about 5.0 s on cellular (review run). On each wifi cell one answer call loses
   a chunk on all four attempts, runs out of `max_retries = 3` and ends
   `transport_error`; its turn is `aborted`, 7.0 s of the cell's 34.3 s. That is also why
   `ttft_p50_ms` is undefined on the wifi cells: a call with no first token makes the
   replicate's value undefined (HYP-11). The retry share is the same at every placement
   because it is one draw: all bundles share a seed and the loss schedule goes by message
   index, so every placement meets the same 10 (wifi) or 5 (cellular) drops.
5. **The stand-in control lost nothing**: 0 drops in its bundles. Had it lost a message,
   it would have waited 600 s, not retried.

### The twin

Live against sim, absolute difference in network share, tolerance 0.02:

| | agent | stand-in control |
|---|---|---|
| edge | 0.004 to 0.005 | **0.056 to 0.070** |
| regional | 0.004 to 0.006 | 0.006 to 0.011 |
| remote | 0.002 to 0.003 | 0.016 to 0.017 |

The review run reproduced these ranges within live noise.

6. **The agent arm is within 0.006 everywhere, and the gap is one-sided.** Live is higher
   on all nine cells (review run): `edge, wired` is 0.74% in sim and 1.29% in live, and
   `regional, cellular` is 4.67% in sim and 5.14% in live, so the two modes disagree on
   which side of 5% that cell falls. `retry_share` has no tolerance in the candidate and
   was 0.274 in sim against 0.308 in live on `edge, wifi`: after the first cut the two
   modes no longer meet the same loss schedule.
7. **The control fails the twin on the three edge cells**, so the twinned verdict is
   `inconclusive` (`twin_failed`), although the decision cell is within tolerance. The
   cause, from the review run: the live proxy delivers each message about 1.7 to 2.9 ms
   after its modelled time (timer slack, EMU-43), at every placement. The link rows
   record it and attribution counts it as network: about 8.9 ms an exchange against
   5.0 ms modelled. So at the edge live's network share is *higher* than sim's (0.238
   against 0.176). A live exchange also gains about 3.6 ms in the served mock and
   1.3 ms of `other`. At `regional` the effects nearly cancel, and at `remote` the
   longer denominator wins and the difference is just inside the tolerance.
   **Sim and live part where the modelled delay is small beside about 2 ms of timer
   overshoot**, not where the exchange is short. The size of the overshoot on a release
   build or another machine was not measured.

### What SPEC 110 has to decide

- **What "placement" and "profile" mean**, with numbers that come from somewhere. These
  are guesses. The measured 5G trace is one profile that is not a guess.
- **What loss means on this link.** Either the scenarios of an atlas carry no
  message-level loss, or the emulator gets a reliable-transport stage (a SPEC 020
  change), or the atlas fixes the request timeout, the retry cap and the backoff as part
  of its design and reports them. Reporting `network + retry` is not enough: a lost
  request is already network time, 600 s of it. Findings 3 and 4 stand in the way of
  every lossy cell.
- **The control, and the direction of the comparison.** T13b's plain-RPC control needs
  its span in SPEC 010 first (Class C). Then: is the claim "an agent turn is less
  sensitive than a request/response call", or "the agent's share stays under a
  threshold"? The second needs no control to state, and CON-18 still wants one.
- **The quantity.** A share falls when the turn gets longer for any reason (finding 3).
  Added seconds a turn, or the share at a fixed model speed, may be the better atlas.
- **The model's speed is the hidden axis.** The crossing moves with tokens a second and
  answer length. An atlas on the mock is an atlas of the mock's profile.
- **The twin where the modelled delay is small** (finding 7): a floor on the modelled
  delay of a twinned cell, a tolerance that knows the proxy's overshoot, or a proxy
  that corrects for it. Finding 6's one-sided gap is the same effect on the agent arm.
- **Scenarios in `acn loop run`** (ADR-34's deferred `env-change`), or the atlas stays
  hand-driven. A frozen file is `grid` only (HYP-9), so "the bisection driver for the 5%
  boundary" needs SPEC 080 §6 question 2 answered first, or the boundary is read off a
  finer grid.
- **Replicates and length.** Four replicates of four turns is a smoke test. A frozen
  file needs 20, and live time grows with it: this grid at 20 replicates is about
  25 minutes of live on the wired cells, and 10 minutes more for every lost request
  until the timeout is set to something an atlas means.

### Known biases

- Mock model, one profile (`mock-auto`), fixed 20 ms a token.
- Guessed link numbers; no outage; one-path scenarios; tools are local, so only the
  model hop is on the link.
- Four replicates, one seed, so every placement sees the same losses; no interval is
  quoted for that reason.
- Debug builds of `acn` and of the driver.
- Live is loopback on one machine.
- The bundles are not kept: they were written to a scratch directory. Sim regenerates
  bit for bit from the files here; live does not.

## Graduate / park / drop

**Recommendation: do not graduate yet; write SPEC 110 next, from the list above.** The
run path is ready for a wired-only atlas today. The lossy profiles and the control are
not: a lossy cell depends on the retry backoff, the retry cap and the 600 s timeout
before it depends on the link, and each needs a decision the maintainer makes: the first three items of the list.
A reasonable first SPEC 110 is the wired column alone, placement as a finer grid of
round-trip times, the measured 5G trace as one extra row, and the stand-in control named
for what it is until T13b lands.
