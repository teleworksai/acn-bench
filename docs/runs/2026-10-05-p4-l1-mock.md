## What the mock does differently from the providers (SPEC 100 P4-12)

These differences are stated with the effects they touch, as P4-12 requires.
- **`tool_order_stable`.** The mock calls the tool at a position (MLM-40), so shuffling the tools also changes which tools are called, not only what is cached (issue #26, recorded rather than fixed).
- **`compaction_trigger`.** The compaction call forbids tools (HAR-4). On `anthropic` that change of tool choice may invalidate cached message blocks that the mock still reads.
- **`fanout_prompting`.**
  - Forked children are restricted by `allowed_tools` on `openai` and the mock, but only by an instruction line on `anthropic`, `vllm` and `sglang` (HAR-14).
  - The fork arm also carries that extra line.
  - A tool-less forked child on `anthropic` sends a tool choice its parent did not.
- **`cache_breakpoint_placement`.** The mock reads only the prefixes the current request marks. Anthropic also looks back to earlier block boundaries, so `rolling_tail` is weaker on `mock-explicit` than on `anthropic` (issue #32).

## What this run fixed on its way

The first complete attempt found that `mock-explicit` counted cache writes over the prefix read. That made `cost_per_success` undefined in every `rolling_tail` cell (issue #12, fixed by T06b4, ADR-28). Before that, the review of T06b found that compaction summaries and forked children were degenerate on the mock (issues #24 and #25, fixed by T06b2, ADR-26). The trajectory was thinned so that the run takes minutes rather than about 20 hours (T06b3, ADR-27).
