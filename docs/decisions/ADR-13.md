# ADR-13 — T02b: run identity, the bundle, and the readings it fixes

**Status:** accepted (T02b, Class C: it adds the Parquet writer settings to the frozen schema module). **IDs affected:** CON-5, CON-26 to CON-31, TRC-1, TRC-19, TRC-22 to TRC-27.

## Context
T02b is the third step of ADR-11: identity hashing with known-answer vectors, environment and build identity, the span model, the OTLP-shaped Parquet writer, the seeded id generator, the bundle with its manifest, and `acn bundle verify`. Writing them needed choices that SPEC 000 and SPEC 010 leave open, and one place where a spec's factual premise no longer holds.

## Decision
- **Known answers are computed outside the crate.** Every vector in `crates/acn-trace/tests/{identity,env,ids}.rs` (replicate seed, sub-stream seed and its first raw ChaCha20 outputs, `params_hash` with a float parameter, `run_id`, the tree hash, the first seeded trace and span ids) was computed from the preimage layout as CON-27 to CON-30 state it, with an independent BLAKE3 and an independent ChaCha20 keystream, not with this code. The preimage bytes are asserted too, so a failure says which field moved.
- **serde_json does not write ryu's form any more.** CON-27(c) says a float is written "exactly as the `ryu` crate formats it, which is the form `serde_json` emits (`1e21`)". serde_json 1.0.151 writes `1e+21`. The normative rule is ryu's, and `identity::float_text` follows it (ryu pinned exactly). No float reaches a hashed or manifest text through serde_json's formatter: the manifest has no floats, and its canonical writer refuses one. The parenthetical in CON-27(c) should be corrected in a `spec-change` PR; `verdict.json` (T05) must use `float_text` too.
- **Generator crates.** `rand_chacha =0.10.0`, `rand_core =0.10.1` and `ryu =1.0.23` are pinned exactly (CON-5(a), CON-27(c)). The golden vector of the first raw outputs of a named sub-stream is in the identity tests; the ranged-integer and distribution samples CON-5(a) also asks for arrive with `rand`/`rand_distr` in T10, so CON-5 stays out of scope.
- **One environment walk.** The ADR-4 walk, the record and the CON-27(b) tree hash live in `acn_trace::env`; `cargo xtask env-hash`, the run preflight and `acn-cli`'s build script all call it, so the gate and a run cannot disagree about which bytes are frozen. `source_files` skips `crates/<crate>/target` only, as CON-31 says.
- **A bundle needs a preflight.** `env::preflight` makes the CON-28 checks and returns a `Preflight`; `Bundle::create` takes one and refuses a run whose hypothesis is not the one the preflight checked (a frozen run checked as `none` or as a candidate). No `acn run` exists yet; T03/T04 call the same function.
- **Build identity.** `acn-cli/build.rs` computes `build_hash`, its components and the `engine_hash` of the frozen code, with `acn-trace` as a build dependency without the `io` feature. Strings are embedded hex-encoded, because `CARGO_ENCODED_RUSTFLAGS` holds `0x1f` separators that `rustc-env` cannot carry. Features are recovered in their manifest spelling by matching `CARGO_FEATURE_*` against the `[features]` keys. `acn version` prints `build_hash`, the whole build record and `engine_hash`; a test checks every component against the working tree.
- **The attribute union is a struct.** TRC-25 types `attrs` as `Map<Utf8, Union{Utf8, Int64, Float64, Bool, Binary}>`. Parquet has no union type and arrow-rs refuses to write one (ARROW-8817), so the map value is a struct of the five members, nullable, in that order (`schema::parquet::ATTR_MEMBERS`), with exactly one set; a test asserts it. OTLP array values have no member and are refused, never flattened.
- **The map keeps every attribute.** A promoted attribute is both in `attrs` and in its typed column, so OTLP export (T02d) reads one place and analysis another. Map keys are in bytewise order.
- **Events and links.** Both carry `trace_id` and `span_id` and a `seq`, the position among the span's events or links. Events are stored by `(time_ns, trace_id, span_id, seq)` and links by `(trace_id, span_id, seq)`; TRC-25 fixes only the span order.
- **Resources** are deduplicated and numbered in the order of their sorted attributes, so `resource_id` does not depend on which tracer provider exported first. `otel::producer_resource` builds a resource from an empty builder, so no detector and no `OTEL_*` variable can add to it (CON-29). The bundle refuses a resource without `service.name`, `service.version`, `acn.engine_hash` and `acn.build_hash`, or naming another engine or build than the run's (TRC-19). TRC-19's ban on commit identifiers is not machine-checkable, so TRC-19 stays out of scope.
- **Writer settings** are set explicitly, every one: zstd level 3, 65 536-row groups, page statistics, dictionary encoding, 1 MiB data and dictionary pages, format 1.0 pages, and a fixed `created_by` that names no version, time or host. They are constants in `schema::parquet`, so a change moves `engine_hash`; the library's own version is in `Cargo.lock` and so in `build_hash`. The Arrow schema stays in the footer metadata; it is deterministic.
- **Timestamps.** Producers set every time explicitly as `UNIX_EPOCH` plus the run clock's offset, and the collector stores nanoseconds since `UNIX_EPOCH`, so `sim` starts at 0 (TRC-26). Anything the SDK dropped (attributes, events, links over its limits) is an error, not a quiet loss.
- **Manifest layout.** `build` is one object holding `build_hash` and its components, with no second copy at top level. `producers` is derived from the resources' `service.name`, sorted. `execution_order` is a list of strings, opaque until SPEC 050/085 define cells; it and `started_at` (RFC 3339, supplied by the caller, who owns the clock) are present in `live` and `netem` and absent in `sim`. `endpoint_host` is required for every backend but the mock and absent for the mock in `sim` (CON-26). `params` must repeat `backend`, `model`, `hyp_status` and `replicates` exactly. Absent optional fields are omitted, never `null`.
- **Verification** parses the manifest strictly, requires its exact canonical bytes, recomputes `run_id`, `params_hash` and `build_hash`, requires the directory to be named by `run_id` and the four tables to be listed, and fails on a changed, missing or unlisted file or a symbolic link. `sidecar/` files are listed like any other.
- **Dependencies.** Arrow and Parquet 60 (subcrates, Parquet without default features: no CSV, CON-4), OpenTelemetry 0.33 with only `trace`. `tracing-opentelemetry` is not added until a producer needs it. Arrow brings `ahash`, built with a compile-time random seed (`const-random`, whose `tiny-keccak` is CC0-1.0, now allowed in `deny.toml`). The seed decides hash-table placement only: dictionary keys are assigned in insertion order, so file bytes do not depend on it, which the determinism suite checks within a build and across processes. `ahash::AHashMap` and `AHashSet` need `ahash/std`, which this tree does not enable, so their `clippy.toml` bans carry `allow-invalid`, as the bans on version-dependent paths already do.

## Consequences
`trace-scope.toml` gains CON-27 to CON-31 and TRC-23, TRC-24, TRC-25 and TRC-27. TRC-22 waits for the views (T02c), and TRC-26 waits for clock-offset correction (T02d). CON-28's kit clause and CON-29's live-option clause bind the kit (T16) and the harness (T04); the functions they need exist and are tested. `env_hash` and `engine_hash` move in this PR. The determinism acceptance suite compares whole bundles across two runs and across processes; it switches to an `acn-emu` scenario at T11.
