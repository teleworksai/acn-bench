# ADR-12 — T02a: the schema module as data, and the readings it fixes

**Status:** accepted (T02a, Class C). **IDs affected:** TRC-2, TRC-3, TRC-12, TRC-14, TRC-20, TRC-21, TRC-25, TRC-31 to TRC-34, TRC-37, TRC-38, CON-29.

## Context
T02a fills the frozen schema module (ADR-11). SPEC 010 names the attributes in prose; turning that into a typed inventory, a view schema and provider mappings needed choices the spec leaves open. They are recorded here because the files are in the frozen set, and each reading becomes expensive to change once bundles exist.

## Decision
- **The schema is data.** `SEMCONV_VERSION`, `acn_attributes.toml` and `views.toml` are embedded and parsed strictly (`deny_unknown_fields`, one error naming the offender). Code in the module only loads and validates.
- **The spec and the inventory are checked against each other, both ways.** A test extracts every back-ticked `acn.` name from SPEC 010 and requires the inventory to list exactly that set, so a name added to either side alone fails.
- **Units follow the suffix, and the loader enforces it:** `_ms` is a float in milliseconds, `_ns` an integer in nanoseconds, `_tokens` and `*bytes*` integers, `_kbps` a float; booleans carry no unit.
- **Views hold integer nanoseconds.** A `_ms` float attribute becomes a `_ns` column once, by round-half-even of the value times 1e6. A time the spans carry as timestamps (durations, time to first token) is computed from the timestamps and never from the float, so no verdict rests on a decimal-to-binary conversion.
- **Absent means null.** Every token count on `chat`, the cache counts included, is optional with the condition "the provider returned usage". `acn.cache.write_tokens` is 0 only when usage was returned and the provider has no cache-write count.
- **Run options are recorded.** `acn.stall_threshold_ms` and `acn.keep_content`, which SPEC 010 names in passing, are required session attributes that record the values of `opt.stall_threshold_ms` (default `250.0`) and `opt.keep_content` (default `false`), so a bundle states the options it ran under. Defaults are written in the text form of CON-27(c).
- **`acn.fanout.parent_lineage` is a string** of 16 lowercase hex characters, the way viewers show span ids, not a byte array; it can then be a promoted scalar column.
- **Promotion.** Every scalar span attribute is promoted except the two large strings, `acn.scenario.toml` and `acn.harness.knobs`. Resource attributes live in `resources.parquet` and are not promoted. `acn.ingest.clock_offset_ns` sits on `*`, any span.
- **Provider mappings.** The input total is a sum of fields, because Anthropic's `usage.input_tokens` excludes cached tokens and OpenAI's `prompt_tokens` includes them. vLLM and SGLang are mapped through their OpenAI-compatible response fields (`usage.prompt_tokens_details.cached_tokens`): SPEC 010 mentions their prefix-cache metrics, but a server-wide metric cannot be attributed to one call. Anthropic's `refusal` maps to `content_filter`; any stop value that is not listed maps to `other`, and the raw value is always kept. The first listed input field is the provider's base count: when it is absent there is no usage.
- **The view schema lists more than the spec's prose.** SPEC 010 says "identifiers"; the views carry `run_id`, the session, turn, call and tool span ids, and a few columns the prose implies (`deadline_ns`, `server_queue_ns`, `streamed`, `tool_name`). Additions are free until T02c writes the views; removals are not.
- **The emission check reads tokens.** `docs-inventory` tokenises every file under `crates/*/src` and fails, in write mode too, on an `acn.` string literal the inventory does not list. A name inside a macro is seen; a name in a comment is not. Test directories are not scanned.
- **`xtask` depends on `acn-trace`** so that one parser reads the inventory. When Arrow and Parquet arrive (T02b) they go behind a feature that `xtask` does not enable.

## Amendment (adversarial review, CON-16b) — what the frozen files must say themselves
A separate session reviewed this PR as a Class C change. Its findings were about data that would have been expensive to correct once frozen.
- **No invented zeros.** A missing cache-read field is zero only for a provider that always reports it (`cache_read_absent = "zero"`: Anthropic, the mock). vLLM reports the count only under `--enable-prompt-tokens-details`, SGLang only under `--enable-cache-report`, and both, like OpenAI, may omit it: for them a missing field is unknown. The first version returned 0, which a per-provider cache verdict would have read as "no cache hits".
- **The rules live in the frozen file.** The provider section of `acn_attributes.toml` now states them, and `normalise.rs`, which is outside the frozen set, adds none: paths address the complete response object (for a streamed call, what the stream assembles to, with the merge rule per wire format); `input_tokens_base` names the provider's own prompt count; a usage object without it is an error (an OpenAI Responses API body, which is not mapped); a count must fit a signed 64-bit column, a sum that overflows is an error, and a cache-read count above the total is an error.
- **A provider cannot claim what only the harness observes.** No provider value may map to `client_abort` or `transport_error`; a server-side `abort` is `other`. Anthropic's `pause_turn` and `model_context_window_exceeded` are listed. The five tables are pinned by a test, because the `other` fallback would hide a typo.
- **`acn.call.new_input_tokens_method` is required.** TRC-12 marks the counts optional, not the method, which is a property of the run (HYP-20).
- **Partial sums do not pass for totals.** A view sum over values that may be absent is null when any term is absent; `calls_with_usage` says how many calls reported. `ttft_ns` is defined for a non-streamed call (TRC-12). `fanout_depth` joins the turn view so that every Appendix A key can be mapped. `outcome_counts` and `outage_id` have stated tie rules. Conversions happen per span before aggregation, and aggregates are integer sums.
- **Option defaults have one spelling.** The loader parses a default as its declared type and requires the CON-27(c) text; `250`, `2.5e2` and `False` are rejected. An option differs from its default when its parsed value, written as CON-27(c), is not byte-equal to it. An option records into one required `acn.session` attribute of its own.
- **Order is stated.** Promoted columns follow the file order of the inventory; view columns follow the file order of `views.toml`.
- **The two files are checked against each other.** Where a view column copies an attribute, it is nullable exactly when the attribute is optional and its type can hold it; `row_per` is a declared span; message content cannot be a source (TRC-42). Span kinds and parents are checked lists; an event field can carry a closed value set; duplicates in any list are rejected; a unit on an attribute needs the suffix.
- **The emission check flags every literal that starts with `acn.` or `opt.`** and is not a listed name, which catches names built with `format!` or `concat!` and misspelt ones; only `crates/<crate>/tests` is skipped.

Still open, for the owner: `acn.tool.requesting_call` is required, as TRC-13 says, so a tool the harness starts without any chat asking for it has no honest value; that needs a `spec-change` before T04. `stream_options.include_usage` changes what is sent to a provider, so CON-29 makes it an `opt.` parameter when T04 adds real backends. `acn.link.id` is read as the scenario's name for the link until SPEC 020 defines it.

## Consequences
`env_hash` and `engine_hash` both move in this PR, as they will in every T02 PR that touches the schema. `trace-scope.toml` gains TRC-2, TRC-20 and TRC-21; the view and promotion requirements are cited and enter scope with the writers that are checked against this data.
