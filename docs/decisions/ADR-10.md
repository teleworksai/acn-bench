# ADR-10 — Pre-landing review of the integrity specs: what a run is bound to, and what a verdict may conclude

**Status:** accepted (spec-change, foundation integrity). **IDs affected:** CON-5, CON-7, CON-8, CON-25, CON-26, CON-27 to CON-31, TRC-11 to TRC-14, TRC-19, TRC-21 to TRC-23, TRC-27, TRC-33, TRC-35, TRC-36, TRC-38, HYP-2, HYP-3, HYP-6, HYP-9 to HYP-16, HYP-20 to HYP-24, HYP-26 to HYP-28.

## Context
Three reviewers read the specs as implementers and as someone who wants a positive verdict on a false hypothesis without breaking a MUST. They found places where two implementations would hash different bytes or reach different verdicts, and moves that the rules allowed. One observation organises the rest: `sim` has no sockets, so a sim bundle can only use the mock backend, a mock-gated verdict is never citable, and every citable verdict therefore comes from live runs against real providers, the one mode where the seed does not determine the data and `run_id` does not identify it.

## Decision
- **Runs are bound to `engine_hash`.** `env_hash` covers every frozen hypothesis, so as a `run_id` input it made freezing one POC invalidate every other POC's bundles. `engine_hash` is the same construction over the frozen crates only; the hypothesis, scenario and workload enter `run_id` through their own hashes (CON-28, ADR-4 amendment 3). The binary embeds the `engine_hash` it was built from and refuses a checkout that differs.
- **CON-27 becomes five requirements** (encodings, root and hashes, run identity, seeds, build identity), each with its own citing test and a known-answer vector added by the PR that implements it.
- **One reading per encoding.** File hashes are of working-tree bytes, never git blobs. Inputs are one defining file that names what it reads by BLAKE3; the tree hash is for source only. Floats are written as `ryu` writes them; a `range` parameter is always a float. The context string is bare; `pairs` has a stated layout. Derived seeds are 63-bit so they fit every signed field. Sub-streams are scoped to the replicate or to the run. The manifest leaves `logs/` out of its file hashes and has a fixed byte form.
- **Identity covers what changes results.** `model` and `hyp_status` join the run parameters; option defaults live in the frozen attribute file; live-mode options must be parameters; `build_hash` gains the cargo configuration and rustflags. A bundle is never overwritten, and `bundle_digest` names the data where `run_id` names the experiment; verdict ids are over both.
- **A verdict may fail on incomplete data and may not pass on it.** Connectives are Kleene, values strict: a true falsifier refutes even with cells missing, so a crash cannot shield a hypothesis; a pass needs a false falsifier with nothing undefined.
- **The guard reads counters only**, and is evaluated once, at file level. A guard that could read outcomes could turn every fail into inconclusive.
- **Providers cannot be dropped quietly.** A slice with any submitted bundle that is inconclusive makes the file inconclusive; every declared provider is listed with its status; `partial-providers` labels a verdict that left some out. The pre-registered minimum of `hypotheses/p4.toml` is kept, and the stricter rule is an open question.
- **Admission checks comparability.** A verdict refuses arms or twins that differ in scenario or workload, slices that mix backends or models, a provider value that disagrees with the backend, mixed builds within a mode, mixed token-counting methods, and inputs outside `[design].pins`. A frozen real-provider file without pins yields `unpinned-inputs` verdicts, which are not citable; this keeps `p4.toml` loading unedited while saying what it still needs.
- **Frozen files are grid designs with at least 20 replicates.** Adaptive designs choose cells after seeing data, and a percentile bootstrap over four pairs is not a 95% interval.
- **The verdict seed depends on the hypothesis alone**, so adding ignored replicates or twin bundles cannot be used to search resampling noise. Percentile indices use a rounding rule that does not depend on floating-point evaluation order.
- **The twin rule says what it is for.** It licenses promotion between loop layers; it names decision cells computed from the sim bundles, requires tolerances for every quantity the predicate reads, bounds them, and checks the divergence of the effect as well as of each arm.
- **Lint rejects a falsifier that cannot fire**, by searching for a witness pair over probe values.
- **Causal, not temporal, tool attribution.** The harness records which call requested a tool; views no longer infer it from timestamps. Turn outcomes are decided by the workload's checker.

## Consequences
`cargo xtask env-hash` must compute `engine_hash` before T02 writes it into a manifest. `hypotheses/p4.toml` loads unchanged and needs a Class C edit (pins) before a real-provider verdict on it can be cited. SPEC 080 §6 lists what these specs do not solve: the seed can still be chosen before freezing; runs never kept leave no trace; replicates on a shared provider are not independent; POC 4's statistic is uncalibrated; and several rules assume a second person who does not exist yet. Those go to SPEC 100, SPEC 040 and the SPEC 085 follow-up.
